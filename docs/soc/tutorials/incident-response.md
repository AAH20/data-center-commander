# Tutorial: Incident Response

> **Estimated Time:** 20 minutes  
> **Prerequisites:** [Getting Started](getting-started.md) completed

---

## Overview

This tutorial covers responding to security alerts generated by the SOC monitoring stack. You will learn to:

- Interpret Prometheus alerts
- Investigate compliance violations
- Respond to critical findings
- Use Kibana and Grafana for forensic analysis
- Remediate issues and verify resolution

## Alert Severity Levels

| Severity | Label | Response Time | Example |
|----------|-------|---------------|---------|
| Critical | `critical` | Immediate (5 min) | Public exposure, critical findings |
| Warning | `warning` | 30 minutes | High findings, compliance drop |
| Info | `info` | Next business day | Storage growth, target down |

## Scenario 1: Critical Finding Detected

### Alert

```
Alert: IACCriticalFindings
Expression: iac_checkov_failed_critical > 0
Severity: critical
```

### Investigation Steps

**1. Identify the failing check:**

```bash
# Query Prometheus for critical findings
curl -s http://localhost:9090/api/v1/query?query=iac_checkov_failed_critical | jq

# Or check the exporter directly
curl -s http://localhost:9091/metrics | grep iac_checkov_failed_critical
```

**2. Find the specific check in Checkov output:**

```bash
# Search Checkov JSON for critical failures
cat /tmp/checkov-results/*.json | jq '.results.failed_checks[] | select(.severity == "CRITICAL")'
```

**3. View in Grafana:**

Open http://localhost:3000 → **IaC Security & Compliance** dashboard → **Failures by Policy Category** panel.

### Common Critical Findings

| Check ID | Description | Remediation |
|----------|-------------|-------------|
| `DC_NET_001` | Publicly exposed security group | Restrict CIDR to internal ranges |
| `DC_STORAGE_001` | Unencrypted S3 bucket | Enable default encryption |
| `DC_CRYPTO_001` | Unencrypted EBS volume | Enable encryption |
| `DC_IAM_001` | Overly permissive IAM policy | Apply least privilege |

### Remediation Example

```hcl
# Before (failing)
resource "aws_security_group" "example" {
  ingress {
    from_port   = 0
    to_port     = 65535
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]  # CRITICAL: Publicly exposed
  }
}

# After (passing)
resource "aws_security_group" "example" {
  ingress {
    from_port   = 443
    to_port     = 443
    protocol    = "tcp"
    cidr_blocks = ["10.0.0.0/8"]  # Internal only
  }
}
```

### Verify Resolution

```bash
# Re-run Checkov
checkov -d /path/to/terraform \
  --external-checks-dir policies/checkov/terraform/ \
  --output json \
  --output-file-path /tmp/checkov-results/

# Wait for exporter to refresh (up to 300s)
# Then verify
curl -s http://localhost:9091/metrics | grep iac_checkov_failed_critical
# Expected: iac_checkov_failed_critical 0
```

## Scenario 2: Compliance Score Drop

### Alert

```
Alert: IACComplianceScoreDrop
Expression: iac_compliance_score < 80
Severity: critical
```

### Investigation Steps

**1. Check current compliance score:**

```bash
curl -s http://localhost:9090/api/v1/query?query=iac_compliance_score | jq
```

**2. Identify which categories are failing:**

```bash
curl -s http://localhost:9090/api/v1/query?query=iac_policy_category_failures | jq
```

**3. View in Grafana:**

Open the **IaC Security & Compliance** dashboard → **Compliance Score Gauge** and **Failures by Policy Category** panels.

### Common Causes

| Cause | Category | Fix |
|-------|----------|-----|
| New unencrypted resources | STORAGE, CRYPTO | Enable encryption |
| Missing resource tags | TAGGING | Add required tags |
| Network exposure | NET | Restrict CIDR blocks |
| Missing logging | LOGGING | Enable audit logs |

## Scenario 3: Terraform Drift Detected

### Alert

```
Alert: TerraformDriftDetected (custom)
Expression: iac_terraform_drift_detected > 0
Severity: warning
```

### Investigation Steps

**1. Check drift count:**

```bash
curl -s http://localhost:9090/api/v1/query?query=iac_terraform_drift_detected | jq
```

**2. Identify drifted resources:**

```bash
# Check Terraform plan output
cat /tmp/tf-plans/plan.json | jq '.resource_changes[] | select(.change.actions[] | . != "no-op")'
```

**3. View in Grafana:**

Open the **IaC Security & Compliance** dashboard → **Terraform Drift Detection** panel.

### Remediation

```bash
# Option 1: Apply the drift
terraform apply

# Option 2: Revert manual changes
terraform apply -refresh-only

# Option 3: Update Terraform state to match reality
terraform import <resource_type>.<name> <id>
```

## Scenario 4: Unencrypted Resources

### Alert

```
Alert: IACUnencryptedResources
Expression: iac_unencrypted_resources > 0
Severity: warning
```

### Investigation

```bash
curl -s http://localhost:9090/api/v1/query?query=iac_unencrypted_resources | jq
```

### Remediation

```hcl
# Enable encryption on storage resources
resource "aws_s3_bucket" "example" {
  bucket = "my-bucket"

  server_side_encryption_configuration {
    rule {
      apply_server_side_encryption_by_default {
        sse_algorithm = "AES256"
      }
    }
  }
}
```

## Scenario 5: Public Exposure

### Alert

```
Alert: IACPublicExposure
Expression: iac_public_exposure > 0
Severity: critical
```

### Investigation

```bash
curl -s http://localhost:9090/api/v1/query?query=iac_public_exposure | jq
```

### Remediation

```hcl
# Restrict public access
resource "aws_security_group_rule" "example" {
  type        = "ingress"
  from_port   = 443
  to_port     = 443
  protocol    = "tcp"
  cidr_blocks = ["10.0.0.0/8"]  # Internal only
  security_group_id = aws_security_group.example.id
}
```

## Using Kibana for Forensic Analysis

### Access Kibana

```bash
kubectl port-forward -n data-center-commander svc/kibana 5601:5601
```

Open http://localhost:5601

### Useful Queries

```
# Find all ERROR logs
level: ERROR

# Find logs from a specific component
kubernetes.labels.app: logstash

# Find security-related logs
message: "security" OR message: "unauthorized" OR message: "denied"

# Time-range: Last 15 minutes
@timestamp: [now-15m TO now]
```

## Alertmanager Configuration

### View Alert Rules

```bash
# Port-forward to Alertmanager
kubectl port-forward -n monitoring svc/alertmanager 9093:9093
```

Open http://localhost:9093

### Silence an Alert

```bash
# Via API
curl -X POST http://localhost:9093/api/v2/silences \
  -H 'Content-Type: application/json' \
  -d '{
    "matchers": [
      {
        "name": "alertname",
        "value": "IACMediumFindingsSpike",
        "isRegex": false
      }
    ],
    "startsAt": "2026-09-29T12:00:00Z",
    "endsAt": "2026-09-29T14:00:00Z",
    "createdBy": "soc-analyst",
    "comment": "Planned maintenance window"
  }'
```
